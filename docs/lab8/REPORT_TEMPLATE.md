# №8 зертханалық жұмыс — есеп үлгісі

**Тақырып:** Университеттің электрондық кітапханасын интеграциялық, жүктемелік және қауіпсіздік тестілеу

## 1. Мақсаты
№7 жобаның компоненттерін бірлесіп тексеру, жүктемедегі жұмысын өлшеу, қауіпсіздік кемшіліктерін анықтау, GitHub Actions орнату.

## 2. Архитектура
Streamlit (8501) → FastAPI (8000) → SQLModel → SQLite (Docker volume). Docker Compose екі сервисті басқарады. **Аутентификация және рөлдер модулі бастапқы жобада жоқ.**

## 3. Компоненттер мен ықтимал қателер
| Компонент | Қате 1 | Қате 2 | Интеграциялық тексеру |
|---|---|---|---|
| Streamlit | API қолжетімсіз | Қате жауапты көрсету | UI→API |
| FastAPI | 422 валидация | 404 жоқ кітап | API→DB |
| SQLite | FK қате | Транзакцияның қайтарылмауы | API→DB |
| Аутентификация (жоқ) | Кіруді тексеру жоқ | Рөл шектеуі жоқ | Қосқаннан кейін ғана |
| API | Қате JSON | Жарамсыз ID | Клиент→API |
| Қауіпсіздік | Қате дерек | Рұқсатсыз жазу | Қауіпсіздік аудиті |

## 4. Интеграциялық және автоматты тесттер
`python -m pytest -v` нәтижесін және скриншотын осында қосыңыз. `tests/test_lab8.py` кемінде 5 интеграциялық тест пен қауіпсіздік/шекара тесттерін қамтиды.

## 5. Деректер қоры
Қосу/оқу/өзгерту/жою және `test_transaction_rollback` тестінің нәтижесін енгізіңіз.

## 6. Жүктемелік тест
Тек **өз компьютеріңіздегі** `http://localhost:8000` API-ге қолданыңыз. Әр сценарийдің Locust CSV есебін сақтаңыз.

| Пайдаланушы | Ұзақтығы | Сұраныс саны | Орташа жауап (мс) | Failures | CPU | RAM |
|---:|---|---:|---:|---:|---|---|
| 5 | 1 мин | | | | | |
| 20 | 2 мин | | | | | |
| 50 | 3 мин | | | | | |
| 100 | 3 мин | | | | | |

50 және 100 пайдаланушы нәтижесін салыстырып, нақты өлшемдер бойынша ұсыныс жазыңыз. CPU/RAM үшін `docker stats` пайдаланыңыз.

## 7. Қауіпсіздік
Бос атау, теріс дана, қате автор, жарамсыз JSON, жоқ кітап ID — бес тексеру. **Пароль, рөл, 401/403 тесттері бастапқы жобада іске аспайды**, себебі авторизация жоқ; оларды орындалды деп жазбаңыз. `bandit -r app -f txt` нәтижесін тіркеңіз.

## 8. CI/CD
GitHub Actions → Library automated tests → соңғы push → test job нәтижесінің скриншоты.

## 9. Қателер мен ұсыныстар
Аутентификация мен әкімші/студент рөлдерін қосу; 422/404 кодтарын түсіндіру; жүктеме кезінде CPU/RAM бойынша ұсыныс беру.

## 10. Қорытынды
Нақты іске қосылған тесттер мен өлшемдерге сүйеніп толтырыңыз.
